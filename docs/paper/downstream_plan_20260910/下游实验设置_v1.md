# 下游修复实验：推荐固定设置 v1

状态：2026-09-10 设计稿；未启动修复。实例使用本目录候选清单，在环境预检后冻结。全部参数必须在正式修复之前确定。

## A. 研究问题和 baseline

主问题：当代码编辑器、输入证据与修复预算一致时，不同定位方法交付的文件候选是否改变实际问题解决率？主实验隔离文件定位效用，不声称同时隔离函数定位质量或完整系统效用。

按用户最新范围更新：不新增 Agentless-FL 定位 baseline。默认五行：LocAgent(adapted)+R、CoSIL(adapted)+R、GALA(adapted)+R、GraphLocator(adapted)+R、MAGNET+R。R 是同一个 Agentless-style 多语言编辑器，不冒充未修改的官方 Agentless-1.5。代码实现可参考本地 CoSIL/agentless，但其 Python 评测与源码处理不能直接套用到 JS/TS/Java。借用 Agentless 的修复部分不要求增加 Agentless 的定位实验。实际衔接方式见同目录《修复器选择与实际操作_v2.md》。

预算只允许四行时，预先确定使用 MAGNET、LocAgent、CoSIL、GALA，GraphLocator 仅保留定位对照，并在论文说明选择理由；不能根据修复结果再排除某个对手。默认五行 K1 为 500 个补丁；四行方案为 400。下文四方法预算与执行步骤指这一精简方案，不再包含 Agentless-FL。

## B. 主实验固定配置

| 项 | 设置 |
|---|---|
| 数据 | SWE50 + Omni50，分别汇总 |
| 定位模型 | 优先使用已有共同模型 Qwen3.5-397B-A17B；冻结真实 API model ID、端点版本与推理预算 |
| 修复模型 | 开发预检中先测试现有 Qwen3.5-397B-A17B 端点的代码编辑能力，满足要求后全方法固定；若换模型在正式实验前统一换 |
| 主方法版本 | 冻结同一实现/config；不能 SWE 用 r5、Omni 用 r4 后称同一方法配置，也不按正式解决率挑版本 |
| 文件候选 | 规范化路径、首次出现顺序去重、验证 base_commit 路径，最多 Top-5；无效项留审计，允许从同一列表后续有效项补齐，规则全方法相同 |
| 文件内源码 | 所有方法共用同一个基于 issue 的确定性检索/打包器；主表不使用各方法不同粒度的函数 hints |
| 代码预算 | 24,000 repair-tokenizer token/例；起始每文件最多 4,000，剩余额度依文件排名重分配；记录实际 token、行号、截断 |
| 公共证据 | 同一去重原始 issue + 一份只根据允许 issue 资产生成的公共证据文本；资产 hash/版本固定，源码打包仅用同一公共输入 |
| 原始图像 | 主表若采用文本修复端点则所有方法均使用公共图像描述；不得将该结果称为直接视觉修复 |
| 独有证据 | 不给 MAGNET 额外轨迹/flow 结论；留给独立证据包实验 |
| 输出 | 统一 SEARCH/REPLACE 块，验证唯一匹配后转 unified diff；代码导出与补丁应用规则冻结 |
| 输出上限 | 8,000 token，支持 reasoning 的端点需另外记录其语义和预算 |
| 采样 | K=1，temperature=0；其他解码参数保持一致，不支持的参数不强行传入 |
| 编辑范围 | 提供的 Top-5 文件；现有文件中的跨文件修改允许；新增文件不受现有路径存在性限制，但须满足统一安全路径规则并单独报告 |
| 工具 | 主实验不额外搜索仓库、不联网、不执行反馈式再修复；测试只作最终评价 |
| 重试 | 网络/服务异常最多重试 2 次；保存全部 attempt，禁止从多个成功响应选最佳；格式错误或补丁失败不追加模型修复 |
| 评测 | 对应 benchmark harness，锁定 revision/容器 digest；开发期依据 no-op/gold 耗时设仓库级统一 timeout，主实验不按方法修改 |
| 分母 | 每集合固定 50，空定位/空补丁/模型失败为未解决；基础设施问题另列、统一重试并报告敏感性 |

代码打包器不能按 gold 选片段，也不能只截取大文件开头。对大文件，使用统一的 issue-query 检索选源代码块，并保留必要 imports/类型上下文；如果采用 LLM 文件内细化器，必须为每种方法相同调用协议，额外计入其成本，并把方法名称说明为文件定位+公共细化+修复。

公共证据成本在系统总成本中对每方法计一次，同时报告物理共享缓存后本次实际花费。所有定位方法应获得一致的原始 issue/公共资产访问条件；已有预测只有在输入/config/快照一致时才可复用。若复用不同配置的历史输出，只能单列为历史系统比较。

## C. 必须与主表分开的实验

1. **函数/实体定位效用**：让所有方法的原生实体 hints 经同一渲染器构成等预算上下文；报告实体解析覆盖率与回退，不与仅文件输入行混排。
2. **MAGNET 证据收益**：固定 MAGNET 文件列表，对比公共输入与额外 MAGNET 证据摘要；总 token 不变。额外说明用于源码的预算是否减少。
3. **Top-k 敏感性**：开发阶段探索 k=3/5/10；正式主表 k=5 不变。若在正式子集报告敏感性，所有方法用相同诊断实例，不按结果选择 k。
4. **Gold-location 诊断**：额外少量开发例只给标准修改位置，不给 gold diff；若仍不能修复，检查编辑器/上下文。属于 oracle 诊断，不是实际 baseline，也不保证是数学上界。

## D. 指标及预算

主指标 Resolved-single：所生成的单个补丁通过官方判定的实例数/50。同时报 Applied（非空且成功应用）/50、空补丁率、失败原因、定位与修复 token、平均和 P90 latency、总成本/解决数。git apply 成功不等于语法通过。

4×100×1=400 个补丁；环境 no-op/gold 约 200 次测试运行（候补/重试另计）。增加 GALA 为 +100 个补丁。扩为 K3 为 +800 个补丁，K10 则共 4,000。定位、公共证据、文件内细化调用和测试计算单独计费。

K3 可使用预声明 greedy+2 stochastic 的混合协议，但命名 Best-of-3 和 Selected@3，不套标准同分布 pass@k 估计。Selected 筛选不能使用隐藏测试；没有合法筛选器时只报告候选潜力，不声称用户可获得 oracle-selected 结果。

每数据集单列 50 例的 wins/losses/ties、百分点差及配对区间；主要比较为 MAGNET vs CoSIL，其他比较探索性报告。每多解决一例为 2 pp，小幅差异不能自动称显著。保留全部逐例结果，避免按成功执行数缩小分母。

## E. 当前结果对应的风险

front_rank_v1 已全部完成，其 File Acc@1=16.30%、Acc@5=69.57%、Strict Acc@5=28.26%、Recall@5=44.17%，final_patch_set recall=17.10%。因此不能预设其下游一定优于历史 r5；候选覆盖、前端排序和小集合选择是三个不同瓶颈。Strict Acc@5 是对参考补丁位置的覆盖，不是解决率上界：有效替代补丁可能修改不同位置。

版本选择只根据事先声明的开发定位/资源标准，随后冻结并完整报告。重复使用基准开发的事实应披露，50+50 不称未见 holdout。

执行顺序：冻结输入与版本 → 在正式名单外约 8 个开发例跑通编辑器（尽量覆盖四语言与图像任务）→ 预检正式候选 no-op/gold → 冻结名单 → 四方法 K1 → 配对分析 → 预声明的预算扩展。开发例中选用能覆盖多种语言的任务，不要求与正式集合不可能同时覆盖的条件。
