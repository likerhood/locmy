# 修复器选择与实际操作 v2

按用户最新范围：不补 Agentless-FL 定位实验，使用既有适配 baseline。本文是实施规划，修复入口尚未实现和验收；未调用收费模型。

## 1. 三个不同对象

- 定位器 L：MAGNET / LocAgent / CoSIL / GALA / GraphLocator，输出有序预测位置。
- 修复框架 R：统一加载 issue 和预测位置对应的源码、构造编辑请求、处理编辑输出并导出 diff 的程序。
- 修复模型 M：R 调用的 LLM。建议先以已有 Qwen3.5-397B-A17B 端点进行开发预检，通过后冻结。

推荐 R 为基于现有 Agentless 修复部分改造的独立多语言编辑器。不是调用 Agentless 的定位阶段，也不是另加一行 Agentless-FL。R 内部可以使用 Qwen；不必因为论文示例用了 Claude/GPT 就购买相同端点。此建议基于现有项目复用成本，不是声称该模型最强或最便宜。

## 2. 接法

已有各 adapted baseline 的 Qwen 定位文件 → 按 instance_id 筛选冻结的50 → 字段白名单转标准有序位置 → base_commit 源码上下文 → 共用 R/M → model_patch → 对应 benchmark harness。

这是离线结果衔接，不要求把全部 baseline 的 agent 类导入 R、不要求重新跑定位，也不把五种方法的候选合并。每方法对每实例独立修复、独立工作目录，R 不接收方法名称。

只有结果缺失、输入/config/源码版本不可追溯或决定更新定位设置时，才需要补跑相应定位器；不要重新运行全部定位来实现文件格式转换。格式错误由适配程序修正，预测本身不能按 gold 改写。

## 4. 修复程序的工程边界

已检查 `CoSIL/agentless/repair/repair.py`：它读取 loc_file、found_files、可选 found_edit_locs，并依赖项目结构获取源码。`agentless/util/postprocess_data.py` 中 check_syntax 使用 ast.parse。需要改造：

1. 显式加载本地清单与问题输入，不固定 SWE-bench Lite。
2. 从已确认 base_commit 的独立 checkout 获取源码。
3. 用所有方法共用的源码打包器，先完成 Top-5 文件输入。
4. 以语言无关的 SEARCH/REPLACE 解析处理输出，不对 JS/TS/Java 使用 Python ast.parse，也不执行模型输出作为 Python 代码。
5. 检查路径、唯一文本匹配和补丁应用；语法/构建测试由语言对应工具或官方 harness 负责。
6. 导出 instance_id、model_name_or_path、model_patch；保留请求级费用、生成失败、原始响应。
7. SWE/Omni 使用各自评测后端，外层从冻结清单重建完整分母。

已有多语言定位适配不意味着多语言修复适配已完成。新增的主要工作是公共修复入口与格式转换，不是再次改造五套定位器。

## 5. 执行批次和验收

P0：锁定预测来源文件和模型身份；使用先前候选清单，不按预测是否命中筛选样本。

P1：实现标准化导出（每方法一份）。文件字段采用对应正式定位评价器实际使用的排序；Top-5 规范化规则见 v1。输出不包含 gold/测试答案。记录 source_sha、方法版本，但这些审计元数据不进入 repair prompt。

P2：实现公共 R，在最终清单之外约 8 个开发例验证四语言、源码提取、编辑解析和评测接口。单补丁 temperature=0、代码24k/output8k作为初始配置；可在开发期调整，正式期锁定。给正确位置的 oracle-location 开发诊断不能向 M 提供 gold patch。

P3：正式候选执行 no-op/gold 环境正负控，异常按预定规则处理，冻结50+50。

P4：默认五方法×100×K1，共500补丁；精简四方法为400。相同 M、prompt、公共证据、代码预算。主实验不重新全仓搜索、不进行测试反馈修复。

P5：官方 harness 测试，逐集合汇总 Applied、Resolved、配对胜负、时间和端到端 token/费用。错误保留在50分母，基础设施异常单独标明。

上述 P1–P5 是待实现流程，不提供伪装成现成可执行的命令。目录可计划为 `downstream/manifests/`、`normalized/<method>/`、`contexts/<method>/`、`patches/<method>/`、`evaluation/<method>/`、`reports/`；目前没有创建收费运行任务。

## 6. 论文方法名称

表行使用 `LocAgent + Shared Repair` 等；表注明确：所有定位器使用同一定位模型，所有预测交给相同、基于 Agentless 修复部分适配的多语言编辑流程，修复模型固定为通过开发验收的端点。

如果以后使用自由搜索/测试循环的通用 agent，应另设实验，固定每种方法的搜索、测试和 token 预算，记录其是否编辑定位范围之外的文件。不能把这种 agent integration 与当前位置受控修复结果混成同一个 RQ 的单一处理条件。
