# rq4work：服务器一键执行与分析

本分支仓库为 `git@github.com:likerhood/locmy.git`，不是外层loccode仓库。脚本使用已经导出的定位，无须重新运行SWE定位。

## 服务器操作

推荐Python3.12、Git、可用Linux Docker daemon，先用1个测试worker。模型通过API运行，不要求本地GPU。镜像与依赖下载需要网络和足够磁盘；具体峰值按仓库测试观察，不保证所有任务都适合小内存机器。

```bash
git clone --branch rq4work --single-branch git@github.com:likerhood/locmy.git /data/locmy
cd /data/locmy/experiment_rq4
bash scripts/server_setup.sh
```

从本地使用scp传输 `.env.local`，或服务器已有父目录mycode模型配置时执行 `cp ../.env.local .env.local`，然后 `chmod 600 .env.local`。不要把密钥提交仓库。若服务器仓库已存在，检查工作区后 `git fetch origin`，再切换对应跟踪分支，不重新clone覆盖目录。

### 一次性完整SWE流程

```bash
bash scripts/server_pipeline.sh --dataset swe --limit 50 --run-id swe50-qwen-k1-v1 --workers 1
```

命令依次执行：创建环境/Agentless → Docker检查 → 安装锁定提交的官方SWE-bench → 拉取锁定revision的官方评测元数据并校验 → 50例gold/no-op环境对照 → 五方法单补丁生成 → 官方测试 → CSV/Markdown/JSON汇总。

默认SWE五方法×50例，共最多250次生成（不包括环境测试）。这一版本不自动跑缺预测的Omni，也不默默换成Qwen3-VL-8B。第一次可使用 `--limit 1 --run-id swe-smoke-v1` 验证整条容器流程；如果据此调参，须将该开发实例从正式名单移出。

**环境不满足会停止，而不是返回虚假成功。** 当前本机没有Docker，因此完整官方评测未实测。锁定上游元数据可能与历史Clean15不兼容；脚本会核对instance_id/repo/base_commit/patch/test_patch/测试列表，任何缺失或变化都停止且尚不调用修复API。这时需提供匹配历史版本的官方评测元数据，不得偷偷更换50例或测试答案。

若已有经核对的完整评测JSONL，可安装harness后执行 `server_run.sh --mode all --eval-dataset /path/to/compatible.jsonl ...`；该文件必须包含image/eval_script/log_parser/eval_type等官方字段。官方源码提交已锁定，pip依赖实际版本记录到reports/server_dependencies.txt。

### 只批量生成，或已有结果单独测试

```bash
# 会调用API；不要求Docker，但不会得到Resolved结论
bash scripts/server_run.sh --mode generate --dataset swe --limit 50 --run-id swe50-generation-v1

# 安装harness、准备评测数据后，评价同一批生成结果
bash scripts/server_run.sh --mode evaluate --dataset swe --limit 50 --run-id swe50-generation-v1
```

generate→evaluate不会自动补做环境正负控；正式实验优先使用all模式。不同run-id是新的采样批次，会重新调用API；同一run-id保持样本、方法、模型、输入hash一致时跳过已记录生成。中断时留下started记录不会自动再收费，该实例暂记unknown，需要人工核实请求状态。不得反复重跑后仅保留最佳补丁。

## 输出位置与解释

结果均在 `runs/batches/<run-id>/`：

| 文件 | 内容 |
|---|---|
| manifest.json | 固定样本、方法、模型、输入/脚本hash、测试超时 |
| records/<method>/<id>.json | 每例生成结果/失败状态/token/耗时/应用检查 |
| attempts/<method>/<id>/ | 原始请求和响应、diff、应用检查 |
| evaluation/<method>/harness.log | 官方容器评测日志 |
| evaluation/<method>/**/report.json | 官方逐例解决判定 |
| control_failure.json | 环境对照失败/缺失清单（如有） |
| per_instance.csv | 每方法每实例明细，包含unknown |
| analysis.json / analysis.md | 汇总与MAGNET对各baseline的配对胜负 |

独立重新分析：

```bash
.venv/bin/python scripts/analyze_batch.py --batch-dir runs/batches/swe50-qwen-k1-v1
```

N使用本次固定清单大小（默认50，smoke则是limit），绝不使用成功请求数作分母。已生成但没有官方报告时resolved为unknown；明确完成生成而没有补丁的系统失败可记为未解决。汇总同时给出unknown数，未知尚未消除的lower bound不能当作完成的解决率。配对未知项单列，不用于胜负判断。

本批次token/时间只包括修复执行，不包含历史定位或模型合同价格，因此不输出伪造美元和端到端成本。本版分析提供描述性配对计数，不宣称统计显著；正式论文区间/检验应在评测完整后按预定方案补充。

## 当前协议边界

修复器仍为独立Agentless-inspired多语言编辑器，不是官方Agentless-1.5原样运行。代码上下文使用完整文件+72k UTF-8字节上限；超限明确失败，不冒充24k token方案，也未实现新文件创建。批量自动化不改变这一边界。正式发表前应冻结/补齐tokenizer-aware上下文协议和统一MAGNET版本，并明确这是开发过的候选集合。

本地验证：9项测试（含gold隔离、补丁可应用、配对分析、重复报告拒绝、缺输入禁止调用、重启不重复收费），Python编译和shell语法检查，以及SWE50×5离线计划检查。Docker官方评测需在服务器验证；未在本次开发中运行250次付费请求。
