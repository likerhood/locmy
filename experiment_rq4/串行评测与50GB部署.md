# 串行评测与 50 GB 部署

本版在 `locmy/rq4work`，必须使用新的 run-id（例如 `swe50-addtest3-mimo-serial-v2`）。旧批次的协议/脚本指纹不同，不直接混用。SWE50 定位与样本本次没有改变。

## 执行方式

固定名单选取前 limit 例后，按仓库、样本 ID 排序执行；名单和统计分母不变。每个样本执行：准备官方镜像并记录 registry digest → no-op/gold 对照 → LocAgent 生成与测试 → CoSIL → GALA → GraphLocator → MAGNET → 保存完成标记。每次测试创建干净容器，测试结束删除容器；同一样本的五种方法共享镜像。禁止 workers 大于 1，使用整个 RQ4 缓存的进程锁防止不同 run-id 并发。

所有阶段均可指定同一个 `--env-file`，包括一键脚本、setup、harness 安装和修复。模型、接口和密码由该文件读取；已 export 的同名环境变量仍优先。配置文件应为普通 KEY=value，不使用 shell 展开或 export 语句。

## 配置文件

```dotenv
RQ4_BASE_URL=https://你的服务/v1
RQ4_API_KEY=你的密钥
RQ4_MODEL=服务商实际模型ID
RQ4_REQUEST_TIMEOUT=180
RQ4_GITHUB_DIRECT=1
RQ4_GITHUB_MIRROR_PREFIX=
RQ4_GIT_TIMEOUT=600
RQ4_GIT_RETRIES=2
RQ4_MIN_FREE_GB=10
RQ4_IMAGE_CACHE=budget
RQ4_IMAGE_PULL_TIMEOUT=1800
```

支持原来的 BASE_URL/API_KEY/MODEL_API_NAME。`RQ4_GITHUB_DIRECT=1` 是默认值：程序加载 env 后会清空 Git 镜像前缀，把 GitHub 主机加入 `NO_PROXY`/`no_proxy`，并传给全部子进程，无需在终端手工 export。如果某台服务器必须使用镜像，设置 `RQ4_GITHUB_DIRECT=0` 和非空 `RQ4_GITHUB_MIRROR_PREFIX`。Git 前缀仍兼容 GITHUB_MIRROR_PREFIX 和 REPO_GITHUB_MIRROR_PREFIX。GitHub 路由不影响 Docker Registry；pip 依赖仍使用服务器配置的包源。

每个项目只保留一个仓库，检查精确 base_commit，缺对象才 fetch；克隆进入临时目录，成功后才发布，失败残留会清理。已有的无效仓库目录不会被强行删除，请检查后移走。下载有低速和超时限制。网络准备失败不会写成已收费的请求。

## 命令（从 experiment_rq4 执行）

仅检查，无 API、无镜像下载：

```bash
bash scripts/server_run.sh --env-file /data2/like/locmy/.env.mimo1.local --mode check --dataset swe
```

单例五方法完整流程，会在该例环境对照通过后调用修复 API：

```bash
bash scripts/server_pipeline.sh --env-file /data2/like/locmy/.env.mimo1.local --dataset swe --limit 1 --run-id swe-mimo-serial-smoke-v2 --min-free-gb 10 --image-cache budget
```

SWE50 五方法完整流程，共 250 个“样本×方法”修复单元；每个单元最多 1 次细定位和 10 次修复候选 API 调用，因此最多 2750 次收费请求，另有 100 次 no-op/gold 对照测试：

```bash
bash scripts/server_pipeline.sh --env-file /data2/like/locmy/.env.mimo1.local --dataset swe --limit 50 --run-id swe50-addtest3-mimo-serial-v2 --min-free-gb 10 --image-cache budget
```

初始化和安装都已完成时，避免重复安装，可直接运行：

```bash
bash scripts/server_run.sh --env-file /data2/like/locmy/.env.mimo1.local --mode all --dataset swe --limit 50 --run-id swe50-addtest3-mimo-serial-v2 --min-free-gb 10 --image-cache budget
```

元数据必须包含官方 image/eval_script/log_parser/eval_type 等字段，并与打包的历史 patch/test_patch/测试列表一致。一键脚本按锁定 revision 下载并严格核对；如果不兼容将停止，不能换用错误测试或悄悄替换样本。若已有经过核对的完整快照，可添加 `--eval-dataset /absolute/path/compatible.jsonl`；一键流程将跳过默认元数据下载，批量程序仍会校验。

仍支持 `--mode generate` 和 `--mode evaluate`。evaluate 现在也会在逐例测试前执行或复用环境对照，不重新生成补丁。generate 批次转 evaluate 时要保留原样本/方法/run-id/模型配置。

## 空间策略

`--image-cache budget`：默认。保留仓库和镜像；低于预留空间时，仅删除本实验新下载、同一 Docker daemon、无使用中/残留容器引用且不是当前样本的镜像。不会调用全局 prune 或强制删镜像。预先存在的镜像不会被接管删除。

`--image-cache sample`：一个样本的所有方法和报告完成后，尝试删除该样本由本实验下载的镜像。不是每测一个方法就删。仍保留 Git 仓库。共享层或其他引用可能让释放量小于镜像显示大小；每次检查实际剩余空间。

检查项目所在分区、DockerRootDir，和存在的 /var/lib/containerd 分区；只支持本地 Docker daemon，存储目录不可见则停止。外置/rootless containerd 的独立存储需要管理员核实实际路径，不能把默认目录检查当成覆盖所有部署。

克隆、镜像拉取、修复和测试子进程运行时每秒检查空间。低于保留值则停止任务，保存 paused.json，保留已生成补丁。监测不是文件系统硬配额；高速写入可能在两次检查间越过阈值，Docker daemon 的拉取取消/清理也可能延迟。不能保证任意镜像都适合 50 GB。先试一个实例并检查 `df -h`、`docker system df -v`。

安装阶段监测项目分区，一键入口也预查 Docker 分区；安装不会清理 Docker。若已有镜像占满空间，先明确释放哪些实验资源，再重启；不要靠降低预留量掩盖容量问题。

## 恢复和结果

同一命令、同一 run-id 重启：跳过完成样本，复用已有对照/官方报告及镜像 digest；已记录的生成不再收费。测试基础设施失败可以重试测试。`started` 表示 API 可能已经发出，中断后不自动重发，必须先核实；该例保持 unknown。接口明确失败也保持 unknown，不伪装成官方测试失败。

`runs/batches/<run-id>/` 中新增：

- `image_pins.json`：每例固定 registry digest；清理后恢复按 digest 拉取。
- `resources.jsonl`：复用、回退、清理和各阶段剩余空间/耗时。
- `image_pull.log`：镜像拉取日志。
- `completed_samples/`：完整评测完成标记。
- `paused.json`：任务中止状态；错误细节还需查看终端及对应 harness/attempt 日志。
- `analysis.md/json`、`per_instance.csv`：实时汇总，未知结果显示 pending，不报告虚假的最终解决率。

环境对照只在同一批次、同一样本、固定测试元数据/脚本/超时和镜像 digest 下复用。修改代码或实验协议须用新 run-id。结果中的修复耗时不是全流程总耗时；资源日志另列下载与评测开销。没有自动计算美元成本。

## 验证范围

本地测试覆盖真实临时 Git 仓库的镜像失败/官方回退/缓存复用，模拟低磁盘终止子进程、保护非本实验和使用中镜像，以及模拟逐例对照/生成/测试/中断恢复。没有在本机运行真实官方 Docker 评测，也没有启动 250 次收费请求。部署代码就绪不代表所有历史样本的官方元数据已兼容；这仍需服务器验证。Omni 同模型输入和评测适配限制不变。
