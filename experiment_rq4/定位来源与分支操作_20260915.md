## 两个分支分别做什么

```text
addtest3 定位代码 → 运行产生 Qwen 定位结果
                               ↓ 导出固定 50 例的排序文件列表
rq4work / experiment_rq4 / normalized/swe/*.jsonl
                               ↓ 同一 MiMo 修复器
                         补丁 → 官方测试 → 分析
```

服务器只运行 RQ4 时，不需要完整 LocAgent/CoSIL/GALA/GraphLocator 项目，也不需要 3.2 GB 的 MAGNET localization_results.jsonl。修复输入是已提交的小型 normalized 文件；gold 字段未导入其中。`configs/sources.json` 的本机路径只用于追溯/重新导出，服务器不要执行 `scripts/prepare.py`。

## 服务器已有 locmy 仓库

先检查本地修改，不要使用 reset --hard 强行覆盖：

```bash
cd /你的路径/locmy
git status --short
git fetch origin
git switch rq4work
git pull --ff-only origin rq4work
git branch --show-current
git log -1 --oneline
cd experiment_rq4
```

如果本地尚不存在 rq4work，将 `git switch rq4work` 换成 `git switch --track origin/rq4work`。如果它已经被另一个 worktree 使用，进入那个 worktree 即可。使用 `git worktree list` 查看位置。

## 服务器还没有仓库

```bash
git clone --depth 1 --branch rq4work --single-branch git@github.com:likerhood/locmy.git locmy-rq4
cd locmy-rq4/experiment_rq4
```

浅克隆可减少代码仓库历史下载；不会限制后续 Docker 镜像或目标项目仓库占用。SSH 需要已有 GitHub 仓库访问权限。

## 配置 MiMo 并检查

```bash
bash scripts/server_setup.sh
nano .env.local
chmod 600 .env.local
```

填写以下专用变量，模型 ID 必须以实际服务支持值为准：

```dotenv
RQ4_BASE_URL=https://你的接口基础地址/v1
RQ4_API_KEY=你的密钥
RQ4_MODEL=实际MiMo模型ID
RQ4_REQUEST_TIMEOUT=180
```

MiMo 是修复模型，不改变 Qwen 定位结果。终端同名环境变量优先于文件；非空 RQ4_MODEL 优先于旧 MODEL_API_NAME。不要保留模板 Qwen 默认值又期望旧变量覆盖它。密钥不提交 Git。

```bash
bash scripts/server_run.sh --mode check --dataset swe
.venv/bin/python -m unittest discover -s tests -v
```

以下单例接口测试会收费并克隆目标项目，但不运行官方容器测试：

```bash
bash scripts/server_run.sh --mode generate --dataset swe --methods magnet --limit 1 --run-id swe-addtest3-mimo-api-smoke-v1
```

更换定位输入后必须使用新的 run-id，不能混用旧 front_rank_v1 批次结果。API 的真实 MiMo 支持仍须实测。本次更新不调用收费接口。

## 只有 50 GB 时的边界

当前代码尚未实现逐样本完成所有方法后精确清理镜像、磁盘阈值暂停和缓存限额；workers=1 仅限制并发。不要直接启动全量 server_pipeline.sh。先检查 `df -h`、`df -i`、`docker info --format '{{.DockerRootDir}}'`、`docker system df`，确认 Docker 分区而非仅项目分区的空闲空间。

后续需实现按样本调度、独立干净容器、保留报告后仅清理本实验资源、断点续跑以及预留空间。单例环境峰值仍可能超过预算。不要运行全局 prune 来清理共享服务器。完整官方元数据兼容性及 gold/no-op 对照仍待服务器验证，不能将接口成功或补丁可应用当成 Resolved。
