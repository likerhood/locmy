## 服务器首次部署

服务器需要 Git、Python>=3.10及venv；正式评测还需要可用Linux Docker daemon与相应harness。远程API生成不需要本地GPU。建议先用1个生成任务与1个测试容器，资源需求取决于仓库构建，不能把本地smoke的内存占用当作全部benchmark的要求。

示例以服务端 `/data/locmy` 为项目目录，USER/HOST需替换。确保该目录可写且服务器Git SSH身份有仓库读取权限。

```bash
# 服务器执行；先完成上面的本地push
git clone --branch rq4work --single-branch \
  git@github.com:likerhood/locmy.git /data/locmy
cd /data/locmy/experiment_rq4
bash scripts/server_setup.sh
```

server_setup 创建独立venv、克隆并检出vendor_lock指定Agentless提交、核对源数据SHA并恢复评测50例、运行预检。它不安装Docker、不安装官方benchmark harness，也不发收费API调用。preflight列出blockers时初始化完成不等于正式实验就绪。

然后在本地安全传输凭据：

```bash
scp /home/like/locCode/alltry/mycode/experiment_rq4/.env.local \
  USER@HOST:/data/locmy/experiment_rq4/.env.local
ssh USER@HOST 'chmod 600 /data/locmy/experiment_rq4/.env.local'
```

服务器中不需要Windows Docker Desktop/WSL Integration设置。普通Linux服务器使用其已有Docker服务；若没有Docker，要依据服务器系统和管理员权限安装，不要照搬本机WSL操作。

## 准备样例源码并开始修复

Git仓库里不包含每个benchmark的源码checkout；已导出的定位文件也不包含完整源码。以下为marked样例准备只读源码对象，修复器使用git show读取base_commit，不需要切换仓库HEAD：

```bash
cd /data/locmy/experiment_rq4
mkdir -p repos
git clone --no-checkout https://github.com/markedjs/marked.git repos/marked
# 检查例子的commit是否存在；若不存在，按输入base_commit执行git fetch origin <commit>
.venv/bin/python scripts/repair.py \
  --env-file .env.local --dataset swe --method locagent \
  --instance-id markedjs__marked-1535 --repo "$PWD/repos/marked"

# 上面离线预演通过后，添加--execute调用一次API
.venv/bin/python scripts/repair.py \
  --env-file .env.local --dataset swe --method locagent \
  --instance-id markedjs__marked-1535 --repo "$PWD/repos/marked" --execute
```

终端会给出本次runs目录。把该目录传给 `scripts/check_patch.py --run-dir ...` 可验证补丁应用，不等于官方测试通过。不要从示例拷贝本机旧runs目录到新的评测命令中。

无需运行 prepare.py：标准化结果已通过Git发布，而该脚本用于本机原始结果归档，sources.json包含原始定位工程的相对路径，单独clone locmy不会包含外层四套baseline。服务器恢复评测数据使用 restore_eval_data.py，绝不依赖本机 `/home/like/locCode`。
